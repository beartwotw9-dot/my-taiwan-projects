# 竹田 AR 真實掃描版｜測試說明

`ar-scan.html` 是新增的**真的會掃描圖片辨識**的版本，跟原本 `竹田頓物驛站_前台旅客AR導覽體驗.html`
不一樣：原本那版是「按按鈕模擬」，這版是用相機真的去比對畫面中的圖片，抓到對應圖片才會跳出內容。

用的是 [MindAR](https://hiukim.github.io/mind-ar-js-doc/)，開源、免費、純瀏覽器端運作，不用裝 App。

---

## 因為現在不在現場，先用「測試圖片」代替 8 個站點

因為場地限制，沒辦法先拿真的木窗、紅磚牆去拍照測試，所以流程設計成：

1. 你先隨便找 **1～8 張有清楚細節、對比度高的照片**（例如書封面、產品包裝盒、有圖案的明信片都可以，
   **避免**單一顏色、太模糊、或重複花紋的圖片，這樣辨識效果最好）。
2. 把這 8 張測試圖片，依序對應「站 1～站 8」（順序很重要）。
3. 之後正式上線前，只要把這 8 張測試圖片換成**現場真正的木窗、紅磚牆等照片**，重新編譯一次，
   其他程式碼完全不用改。

---

## 第一步：把測試圖片編譯成 `targets.mind`

1. 打開 MindAR 官方免費編譯工具（純瀏覽器操作，圖片不會被上傳到任何伺服器）：
   👉 https://hiukim.github.io/mind-ar-js-doc/tools/compile/
2. 把你準備好的 8 張測試圖片，**依照站 1→站 8 的順序**拖進去（一次全部拖進去，順序就是之後的
   `targetIndex 0～7`）。
3. 按 **Start**，等它跑完（圖片越大張，跑越久，正常是幾秒到幾十秒）。
4. 按 **Download**，會下載一個檔名叫 `targets.mind` 的檔案。

## 第二步：把 `targets.mind` 放進資料夾

把剛剛下載的 `targets.mind`，放到跟 `ar-scan.html` **同一層資料夾**：

```
zhutian-ar-guide/
├── ar-scan.html
├── targets.mind          ← 剛剛下載的檔案放這裡
└── 竹田頓物驛站_前台旅客AR導覽體驗.html
```

## 第三步：部署到 GitHub Pages 後用手機測試

**重要：相機權限跟這個頁面的自動檢查功能，都需要 `https://` 或 `localhost`，
不能直接雙擊 `ar-scan.html` 用 `file://` 打開，瀏覽器會擋掉。**

最簡單的方式：照之前給你的 README 步驟，把整個資料夾上傳到 GitHub、開啟 GitHub Pages，
之後用手機瀏覽器打開：

```
https://你的帳號.github.io/你的repo/zhutian-ar-guide/ar-scan.html
```

1. 打開後允許相機權限。
2. 把手機鏡頭對準你準備的測試圖片（可以印出來、也可以顯示在另一台螢幕/平板上）。
3. 對準後畫面下方會自動彈出對應站點的任務卡片，同時最上面的進度條會亮起一格。
4. 8 張都測過一輪，確認每張都能正確對應到期望的站點，就代表掃描邏輯沒問題。

## 第四步：正式上線前，換成真實地點照片

1. 到現場，把 8 個站點（木造舊站售票口、紅磚倉庫……德興碾米機）都拍一張清楚的照片。
2. 重複「第一步」，但這次用這 8 張真實照片，依照相同順序（站1～站8）重新編譯一次
   `targets.mind`，覆蓋掉舊的測試版本。
3. 其他程式碼、樣式、任務內容完全不用動，因為程式邏輯是照 `targetIndex 0～7` 對應站點，
   跟圖片內容無關。

## 常見問題

**Q：辨識率不好、常常抓不到？**
換一張細節更豐富、對比更強烈的圖片；避免使用純色、對稱花紋、或反光很強的照片。

**Q：想要 8 個站點以外更多的目標？**
把 `ar-scan.html` 裡 `[0,1,2,3,4,5,6,7]` 這行，跟 `arData` 物件，一起加上更多筆資料即可。

**Q：想要真的疊加 3D 物件、不只是文字卡片？**
目前 `ar-scan.html` 是用簡單的半透明色塊當佔位（`a-plane`），之後可以換成 `a-image` /
`a-gltf-model` 疊上真的 AR 圖案或模型，這部分可以再請我幫忙加。
